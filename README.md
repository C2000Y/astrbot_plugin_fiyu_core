# Fiyu Core · 肥鱼聊天引擎

版本：**v0.2.7** · 开发目标 AstrBot **4.29.3**（`>=4.29.3,<4.30`）

将群聊读空气、独立人格、分层记忆、表达学习、主动阅读、按需知识查询、Dota 2 数据、跨会话转达、Token 统计和管理页放在一个插件内。使用你已有的 AstrBot 人格、Provider 和知识库，不另启一个 Web 服务，不需要新建 LLM API Key。主要开发目标是 Windows ECS 上的 QQ 官方 WebSocket；同时使用 AstrBot 对 QQ 官方 Webhook、OneBot（aiocqhttp）的通用消息接口。

## 1. 初次安装与启用

1. 在 AstrBot WebUI 打开「插件」→ 上传本地 ZIP，选择 `Fiyu-Core-v0.2.7.zip`，等待加载完成。
2. 进入插件 **Fiyu Core · 肥鱼聊天引擎** 的详情页，打开「可视化视图 / Views」中的 **肥鱼管理中心（dashboard）**。这个页面就是插件的完整配置界面；不使用第二份 AstrBot 原生表单配置，避免两份设置互相覆盖。
3. 在配置中心设置运行模式、群聊白名单、模型和知识库权限。默认是 **off**，不会接管任何会话。
4. 先使用 `observe` 模式短暂观察。它会记录白名单内的近期消息、对非直接请求实际执行部分读空气判断，但**不发回复、不自动学习**；已有聊天链继续运行。观察模式的模型判断仍可能计费。
5. 确认日志能收到两位群友的普通发言、名字请求、真实 @ 后，将旧的 Group Chat Plus、Self Learning、LivingMemory 等会接管聊天、重复学习的插件在对应会话禁用，再切换 `active`。旧插件的数据不要删除，便于回退。
6. `active` 模式接管白名单内 QQ 消息的聊天生成。普通 AstrBot 注册指令和配置的命令前缀让行；独立的天气、股票提醒等定时任务原则上可以保留。依赖原聊天生成钩子的其他插件需要单独联调，见下文。

不需要打开新端口，也不需要把 OpenID/API Key 写进 ZIP。配置保存后在下一次消息/后台任务中生效。停止、重新启用或升级插件不会主动清空其 SQLite 数据。

### 升级至 v0.2.7

从 v0.2.1 至 v0.2.6 升级沿用 SQLite schema 4。已有记忆、配置和工具额度可直接使用。图片理解时机缺省为经济，可在配置中心按需调整。旧配置缺少 `reply.split_on_newline` 且 `reply.split_chars` 恰为 150 时，加载后的兜底长度为 300。其他自定义长度照原值加载。要继续使用 150，可在新版配置中心设为 150 并保存。

1. **正常停止 AstrBot 实例**，备份整个 `core/data/plugin_data/astrbot_plugin_fiyu_core/` 数据目录（包括配置、数据库及存在的 WAL/SHM），另行保留旧插件代码。
2. 用本 ZIP 更新**同一个**插件，不创建新插件名，也不要在卸载时删除旧数据。如果 WebUI 不允许覆盖，保持实例停止，备份并替换 `core/data/plugins/astrbot_plugin_fiyu_core/` **代码目录**为 ZIP 内同名文件夹。不要替换 `plugin_data`。
3. 启动实例，确认管理中心为 v0.2.7。现有 schema 4 数据库直接使用；首次打开更早的数据库时自动制作 SQLite 一致性备份，校验备份，再在事务中升级至 schema 4，沿用 v0.2.1 的备份文件名。v0.2.0 的备份在 `upgrade_backups/v0.2.0-.../fiyu-before-v0.2.1.sqlite3`；v0.1.x 使用原 schema 对应的 `v0.1.0-...` 或 `v0.1.2-...` 前缀。旁边保存 `config-before-v0.2.1.json`（若原配置存在）。备份失败不继续升级。
4. 现有记忆原文、证据、主体/关联用户 ID、重要性、置顶、历史版本、旧日志、Dota 缓存与配置值均保留。v0.2.0 的每个会话人物记录不删除、不改写原身份链接，只新增统一身份映射及按人格的关系表。用户列表将同一个平台实例内相同 UID 汇总为一个档案；展开后仍看到原会话详情。旧好感度有分歧时，选择最近有互动的非默认值（再按最后发言排序），所有旧值原样保留，不叠加不同会话初始分值。旧关系中有朋友则保留朋友，非自动熟悉度采用最近有互动的手动记录。来自 v0.1.x 的旧 `owner` 标签仍自动退休为普通朋友。到 **用户管理 → 展开会话 → 迁移旧称呼** 可逐条预览并确认需要替换的记忆正文。
5. 自主学习、跨会话转达默认关闭，按第 6 节开通；习惯由本人授权；轻量打断与场景化表达默认开启。原运行模式、白名单、模型分工及已有预算值不变。第一次测试建议在低流量群进行。
6. 在总览检查「Dota 版本资料」；正式模式默认自动同步，可点击「同步 Dota 版本资料」开始首轮连续分批获取，等待英雄、装备分别显示已发布。单英雄/装备按需查询不必等待全量同步。原「同步 Dota 统计」和三个统计来源依然独立，`default_rank` / `rank_labels` 仍仅用于对抗。

7. 打开「学习中心 → 自主学习」，点击「检测数据源」验证当前服务器可访问的官方 RSS、API 与 OpenDota。如果此前临时删去了 `cs2_news` 或 `dota_news`，新版本不会擅自恢复这些配置项，需要使用时请手动加回；若临时扩大了每日主题数，可恢复所需上限。重新打开插件视图即可看到新导航。

已经导入 LivingMemory 的记忆不需要再次运行迁移脚本。**旧迁移工具 v1.2.0 针对 schema 2**；如果还有尚未导入的旧资料，先保留/恢复 v0.1.2，完成旧数据导入并验证，再升级 v0.2.4。不要在 schema 3/4 上直接使用旧迁移工具。

回退时正常停止实例，先备份当前新版数据，再恢复旧代码及对应升级前数据目录（或一致性数据库备份与原配置）；不得将旧数据库文件与新版 WAL/SHM 混用。回退快照不会包含升级后新增的记录。升级不补收停机时未投递的聊天消息。

### 1.1 白名单及身份

QQ 官方群的身份是适配器返回的 **OpenID**，不一定是 QQ 群号码。

在群里以 AstrBot 管理员身份运行 `/sid` 或 `/fiyu_id`。后者显示平台、群 OpenID、发送者 ID 和 UMO。群白名单可填群 OpenID，或完整 UMO，例如 `your-adapter-id:GroupMessage:your-group-openid`。不要把这些示例当作真实 ID。

默认不接管私聊；需要私聊时，同时开启 `access.private_enabled` 并填写 `access.private_users`。全局黑名单 `blocked_users` 使用平台真实发送者 ID；用户管理页可统一设置通用称呼、别名和同人格的熟悉度、好感度，也可按会话单独屏蔽、设置专属称呼与拒绝关键词。人格关系与后台权限分离，管理权限不会作为群友身份注入模型。

同群成员通过其稳定身份区分，即使 QQ 没有提供昵称也不会自动把不同成员当成同一个人。从 v0.2.1 起，统一身份以「平台类型 + 机器人适配器实例 ID + 真实发送者 UID」为键。同一实例下一个人进入不同群或私聊，不会再在用户列表中重复出现；不同实例或不同 UID 不因昵称相同而自动合并。涉及不同人格时仍为同一人物档案，但各人格的亲疏关系分别保存。

作用域仍按「平台实例 + 群/私聊 + 真实会话 + 人格」划分，私聊与群聊的原始上下文、记忆、知识库访问权限、专属规则和习惯授权不会互通。统一身份不等于自动跨会话续聊；v0.2.1 不开放任何新跨会话读历史的模型工具。请仅在已获成员知情授权的会话启用记录和学习。

从 v0.1.1 起持久维护 `people.uid`（真实发送者 ID）、`people.ref`（同作用域稳定短 ID）、当前平台昵称、历史昵称和管理员定义的别名。QQ 提供新昵称时更新当前昵称；未提供有效名称时保留上次已知名称。自定义称呼可以覆盖聊天显示，但不改变身份。原昵称与新昵称都能查询记忆。同名/重用历史昵称时要求通过短 ID 确认身份，不猜测合并。机器人应用或平台实例变化时，不会仅凭相同昵称甚至相同 UID 合并不同命名空间的身份。

统一用户档案支持以下操作：

- 「编辑档案」维护适合所有关联会话共享的通用称呼和自定义别名；每个已观察人格有自己的关系标签、好感度、熟悉度。通用称呼留空时使用原会话昵称。
- 「展开会话」查看该人出现过的群聊及私聊、会话身份短 ID、原昵称及专属称呼、互动数和习惯授权；「会话设置」只编辑该作用域的称呼、备注、规则与授权。会话专属称呼优先于通用称呼。
- 历史昵称在后台汇总查询，不会把另一个会话自动观察到的昵称/备注直接注入当前聊天。只有管理员明确维护的通用称呼、通用别名及同人格关系统计在现有会话授权范围内共享。
- 「关联记忆」按统一身份精确检索原有主体/关联人物记忆，可通过会话筛选进一步缩小范围。所有记忆仍保存原作用域及证据；模型运行时只能召回当前会话。

### 1.2 模型配置

| 配置字段 | 建议 |
|---|---|
| `models.chat_provider` | 选择已经配置的 DeepSeek Flash 主聊天 Provider，或留空跟随当前会话 |
| `models.decision_provider` | 选择低延迟、低开销的非思考模型；没有第二个 Provider 时留空 |
| `models.memory_provider` | 选择能稳定输出 JSON 的模型；留空跟随主模型 |
| `models.style_provider` | 留空跟随记忆模型 |
| `models.research_provider` | 可选独立查阅模型；留空跟随记忆模型，再回退主聊天模型 |
| `models.vision_provider` | 选择实际支持图像输入的 Qwen VL 等 Provider；留空不做图片理解 |
| `models.embedding_provider` | 可选。留空，使用本地中文关键词召回，不另花 embedding Token |
| `persona.persona_id` | 选你已有的肥鱼人格 ID，或留空跟随 AstrBot 会话人格 |

Provider 使用的是 AstrBot 中的 Provider ID，而不是单纯模型名。插件不修改 Provider 自身的思考模式、API Key、最大生成 Token 等参数。建议给读空气使用单独、关闭长思考且输出预算较低的 Provider，以避免费用和延迟过高。

## 2. 群聊引擎

- 真正收到的 @、引用机器人消息、配置的名字策略、授权私聊优先响应。`smart` 名字策略通过上下文判断是在谈论肥鱼还是在请肥鱼回答；`force` 则直接唤醒。
- 普通聊天批次默认有 35% 进入模型判断。不是每条消息都发往模型；同一话题连续数条消息先合并，默认静默等待 1.5 秒、最多 5 秒。点名和续聊不受普通采样限制。
- 结合多人的近期消息、发言者标识、当前要回应的消息和角色人格生成回复。普通插话有密度/冷却限制，明确请求仍受每分钟硬限频保护。
- 开放的群聊话题即使没点名，简短反应或相关补充也可获得接话机会。明确在对其他人说话时会让行。普通失败保持安静，直接请求失败给简短反馈。
- 运行日志按 `local_skip`、`model_silent`、`decision_budget`、`decision_error` 区分本地跳过、正常沉默、预算拒绝与故障。故障的 `error_kind` 可用于筛查超时、限频、额度、审核、无效格式及未分类错误。日志记录固定原因码和可核实的状态，不记录模型给出的原因原文。实际调用次数见「Token 用量」。
- 工具查询默认最多 3 轮、6 次调用，之后只根据已有结果总结。若模型把 DeepSeek DSML 控制标记作为正文输出，或返回不完整的结构化调用，插件不执行该异常内容，并在现有预算允许时最多额外发起一次恢复请求。达到工具上限后，恢复请求也不提供工具。正常回复无需额外模型调用。仍失败时给出简短反馈；模型输出在分段前再次检查。已存在的异常机器人历史只在模型上下文和学习中跳过，原始记录保留。
- 排查查询协议异常时，在「用量与日志 → 运行日志」选 `REPLY`，搜索 `tool_protocol_error`、`tool_protocol_recovered` 或 `tool_protocol_retry_failed`。异常记录包含 `tool_rounds`、`tool_calls`、`offered_tools` 和本轮 `turn_id`，便于区分首次查询和最终总结，避免记录原始工具参数。`DEBUG` 下可查看 `tool_final_summary`。
- 配置中心的「对话与回复 → 回复与图片」控制聊天气泡。默认按模型在普通正文中写出的换行发送，一个换行或一个空行都可以另起一条。QQ 客户端随屏宽自动折行不触发分段。榜单按完整条目切分，短榜单、表格和围栏代码块保留内部换行。连续长文默认以 300 字作为兜底目标，最多 5 条，段间延迟 1.5–3.5 秒。完整代码块或段数限制允许单段超过目标长度。单轮总上限仍默认 1800 字。
- 「按模型换行发送」可单独关闭，保留长文兜底。关闭「启用分段发送」或将「最多发送段数」设为 1 时整轮发一条。固定戳一戳及转达确认提示保留原有排版。模型在同一轮生成整段答复，分段无需再调用模型。社交精力按实际有提交的对话轮次扣减。
- 「用量与日志 → 运行日志」选 `REPLY`，搜索 `submitted_to_adapter`。`planned` 是计划段数，`part_chars` 是各段字数，`parts` 是成功提交给适配器的段数。`status` 显示完成、打断、发送失败等原因。整轮零提交时查 `submission_stopped`。`DEBUG` 下还可按 `turn_id` 查看逐段提交时刻。日志仅记录分段统计。
- QQ 官方平台（WebSocket / Webhook）的普通回复在发送前将行首的 `8. 测试甲`、`8) 测试甲` 改为 `8、测试甲`，避免 QQ 渲染独立消息时从 1 开始显示列表。数字和列表正文不重新生成，分段前统一处理，关闭分段仍然生效；小数、行内内容、代码块以及显式原文转达不受此格式转换影响。
- 默认启用轻量打断。正在为某位群友生成/分段发送时，该群友明确说「先别说」「不用查了」等，取消尚未发送的部分；「等等，我说的是……」等明确补充最多触发一次按新上下文重新组织。无关发言不会强行打断，已发出的部分不撤回。参见 `interrupt` 分类。
- 真正收到且目标是本机器人的戳一戳，默认直接发送可配置的固定回复，不走随机概率或 LLM；硬限频依旧生效。QQ 官方适配器 4.29.3 未提供常规群戳一戳事件入口，因此该功能在官方平台无法凭插件单独实现；OneBot 等实际提供事件的适配器才可触发。
### 2.1 图片理解

在「对话与回复 → 回复与图片」启用图片理解，并在模型设置选择真正支持图片的 Provider。图片理解时机提供三个选项。

| 策略 | 行为 |
|---|---|
| 经济（`economy`，默认） | 决定回复后才识别相关图像。 |
| 平衡（`balanced`） | 正式运行时，普通批次通过采样等本地门槛，且只有图片或文字不足以判断时，先识图再决策。 |
| 完整（`full`） | 正式运行时，授权会话的近期相关图像可主动识别，包括普通采样跳过的批次。所有会话合计默认每日 6 次，同一会话至少间隔 60 秒。每日次数设为 0 可停用主动识图。 |

明确 @ 或私聊仍直接进入回复流程。识图默认受 45 秒、每轮 3 张的限制，按图像内容、作用域、Provider 缓存，同一批决策与回复共用描述。原图不写入插件记忆库。识图不可用时保留文字路径，只依据实际取得的描述发言。主动视觉理解单独统计，仍受总预算及 `budget.module_call_limits.vision` 限制。

## 3. 分层记忆设计

重要性、有效期和记忆清晰度是三个不同维度：**重要性不存在统一时间衰减公式**。

| 类型 | 默认行为 | 例子 |
|---|---|---|
| `core` 核心事实 | 保持精确，永久活跃；可设定经过多久只显示语义要旨 | 好朋友生日、长期指定称呼 |
| `profile` 人物记忆 | 稳定事实长期保留，来源必须支持本人陈述；可在后来明确纠正 | 喜欢哪个英雄、稳定爱好 |
| `experience` 经历 | 30 天后清楚、90 天后模糊；重要性≥70的经历至少保留要旨；低重要度经历 365 天后进深层存档 | 一起夺冠、重要共同事件 |
| `ordinary` 琐事 | 默认不记录没有价值的琐事；少量入库的琐事活跃 3 天，通常 7 天后清理 | 周一吃了什么 |
| `temporary` 临时事项 | 按有效期失效；无明确期限默认 2 天；历史仍可检索，不当作当前事实 | 明晚开黑的约定 |
| `habit` 习惯印象 | 经本人同意，多日公开分享后形成粗粒度非确定印象；默认 3 个不同日期、45 天观察窗、30 天无新证据即失效 | 常在周末聊 Dota，喜欢讨论某个游戏 |

每条记忆保存完整事实、语义要旨、短印象和证据编号/摘要。管理员可以置顶，编辑、归档、恢复已归档记忆、查看历史版本、删除。置顶不受时间模糊或普通归档规则影响；已经过期的临时事项依旧会失效。

每条个人记忆自动绑定主体身份，也可关联多个群友。公共事件可用 `group` 作为主体，再连接明确相关的身份。学习时额外从所选证据的发言者、适配器提供且在此会话已识别的 @/引用身份、唯一昵称候选中选择真正相关的人；昵称候选需要模型结合语义判断，重名不自动关联。身份关联与文字正文分开保存，不需要改写旧记忆中的称呼。管理员可在记忆管理中查看实际用户 ID、添加或移除其他相关人物。

自动召回默认最多 3 条相关活跃记忆（800 字符）；不把所有群友资料机械塞进每个回复。主模型还可主动调用 `recall_memory`，指定人物、主题、时间范围，并请求深层细节/过去版本。普通的语义回忆不会自动恢复原本未回忆出的精确细节；真实深层回忆或新证据可以恢复清晰度。自动注入不计为主动回忆。

主动和自动召回携带主体与相关人物的短 ID，按需附带现用/历史称呼；与聊天中的 `speaker`、`current_speaker` 对应。真实平台 UID 仅留在本地身份表和管理员界面，不作为身份元数据发送给模型或 Embedding。身份识别和检索没有额外的模型调用，仍使用原来的自动回忆字符、条数以及工具结果预算；参与者额外别名总量受限。工具预算不足时优先保留完整记录和身份 ID，不输出截断身份。

例：

- 「肥鱼，记住我生日是 7 月 22 日」：符合证据检查后，模型调用即时记忆工具；后台批量整理也能从本人消息提取。
- 「我的生日说错了，是 8 月 9 日」：只在置信度与本人明确新证据支持时更新同一个主题键，旧版本保留。较早的延迟学习不能覆盖较新的内容。
- 如果设 `core_blur_after_days=180`，且语义要旨为「生日在 8 月」，超过对应时间后日常回忆可以只保留月份；完整日期仍在深层记忆中。默认 0 表示核心事实永远精确。

模型提取结果不是事实验证器：程序验证证据编号、作用域、本人发言、关联身份、类型、置信度、敏感字段和更新顺序，但语义内容仍由模型判断。重要信息建议在管理页核对、修正或置顶。schema 1 升级会从已知主体和结构化证据补齐身份，schema 2 直接保留身份关联，无法核实的旧正文昵称不会被强行匹配。尚未导入的 LivingMemory 记忆按第 1 节先使用旧版兼容迁移包。

## 4. 知识库：由 AI 主动查询

此插件的聊天链不按每条用户输入自动触发所有向量库，而是将**明确的函数工具**提供给主模型。示例：

> A：紫猫的残阴这个技能很厉害。  
> B：真的假的，肥鱼帮我看看。  
> 肥鱼：根据 A 和 B 的上下文调用 `query_dota_hero(hero="紫猫", skill="残阴")`，再依据返回的技能资料回答。

查 SAP 文档则调用 `search_knowledge`。在「知识库与网页工具」配置中添加映射：

```json
{
  "alias": "sap",
  "name": "你的 AstrBot SAP 知识库名称或 ID",
  "description": "SAP 官方技术文档、事务码及流程",
  "allowed_groups": [],
  "allow_private": true
}
```

`alias` 是模型看到的工具参数；`name` 是现有知识库。不改动原知识库的索引。群白名单为空意味着此知识库不可用于任何群，仅按 `allow_private` 与私聊总白名单决定访问权限。含非公开业务资料的知识库建议仅开放给经授权的私聊，不要默认公开给群友。只返回选定库的文档名及相关文本片段，不能保证原知识库索引到的文档图片自动成为主模型图像输入。

网页查询复用当前会话的 AstrBot 原生网页搜索服务，需要你先在 AstrBot 配置中启用、选择并填写相应搜索 Provider。插件不直接执行原 Web Search 插件的任意函数，不提供执行系统命令、任意文件或任意 URL 的工具。网页结果可能不准确，模型必须区分来源与事实。

## 5. Dota 2：数值工具与统计工具分离

### 5.1 统计来源与口径

v0.1.2 将三个来源独立同步、校验、储存。普通「现在谁胜率最高」不再使用旧对抗接口的 `win_rate`，也不读取 `default_rank` 作为自身胜率的默认范围。

| 统计 | 数据来源与口径 | 本地快照目录 |
|---|---|---|
| 自身胜率、排名、同口径比较 | OpenDota `heroStats`；默认 `pub_win / pub_pick`（公开比赛总体样本，不等于全部天梯比赛），明确段位按对应 `N_win / N_pick` | `dota/public_stats/` |
| Valve 分组周统计 | `GetPlusStatsData`，原始 `rank_chunk=0..6`、`week=1..8`，提供胜率、选取率、禁用率；数值为 0..1 比例乘 100 | `dota/weekly_stats/` |
| 对抗、同队 | `GetPlusHeroAllyAndEnemyData`；使用 `enemy_win_rate`、`ally_win_rate`，绝不作为总体胜率 | `dota/snapshots/`（兼容旧快照） |

OpenDota `bracket=1..8` 对应先锋、卫士、中军、统帅、传奇、万古流芳、超凡入圣、冠绝一世字段。没有样本的段位（例如 2026-11-23 样本里的字段 8）明确返回无数据，不是 0% 胜率；也不会改用其它范围冒充。字段 8 为空时，不能声称已有独立冠绝一世数据或确定字段 7 是纯超凡入圣样本。Valve 的两个原始分组编号并未取得可核实的段位映射，不能与 OpenDota 直接换算。Valve 周数据默认 `week=1`（根据已有样本推定最近索引），完整提供各原始周索引，具体日期区间未核实，不据此声称某个准确日历周。

校验使用全量英雄 ID、重复项、计数及单位、样本覆盖、`wins <= picks` 等确定性规则。标准完整 5v5 样本按选取场次加权的胜率应接近 50%；允许 ±0.5 个百分点误差，不用英雄胜率的简单平均。Valve 周统计还验证选取率总和接近 1000%（允许 950–1050%）。对抗条件统计不适用总体 50% 校验。校验失败的来源不覆盖旧快照，其他来源仍可更新；返回抓取日、口径、校验信息、有效样本量（若有）、缺失及过期标记。这些校验用于发现异常，不保证统计在其他方面绝对正确。

### 5.2 原有数据复用

你之前的两个 PowerShell 同步脚本不必马上替换：

- **旧 Valve 对抗 JSON 快照目录**：填写 `dota-stats-sync-data\snapshots` 的完整绝对路径。插件只读 `YYYYMMDD.json` 中的对抗和同队资料。旧的自身胜率不能用于新统计，也没有足够证据重建升级前的 OpenDota 历史。
- **旧英雄装备 Markdown 路径**：填写 `dota-sync-data\Dota2-Heroes.md` 文件或其所在目录的完整绝对路径。作为 Valve 详情接口不可用时的旧资料补充。Windows 文件选择器返回的 `/C:/...` 也会按 Windows 盘符路径处理。

例如通过 JSON 配置填写 Windows 路径（请改成真实位置）：

```json
{
  "dota": {
    "existing_snapshots_dir": "C:\\YourBotFolder\\dota-stats-sync-data\\snapshots",
    "existing_catalog_md": "C:\\YourBotFolder\\dota-sync-data\\Dota2-Heroes.md",
    "auto_sync": true
  }
}
```

这里展示的是局部字段；在完整 JSON 中修改 `dota` 对应部分即可。建议启用内置每日同步：正式运行后，北京时间 `sync_hour` 后按来源检查今日快照，成功的来源不重复下载，失败的来源独立退避。超时、网络和临时 HTTP 错误从 15 分钟逐次延长，最多 2 小时；无效 JSON 或结构异常从 4 小时逐次延长，最多 24 小时。失败保留原快照及抓取日期，退避跨重启有效。即使旧脚本已有当天对抗快照，OpenDota 和 Valve 周统计仍会首次同步。总览显示各来源的成功日期、最近尝试、失败原因和重试时间。手动「同步 Dota 统计」可验证失败来源，按来源最短间隔 60 秒，已健康同步的当日快照无需重拉。实测 Valve 对阵响应有缺失配对，继续拒绝该批数据。插件仅写自己的快照目录，不修改原知识库和旧脚本文件；同步不消耗 LLM Token。只保留旧脚本而关闭插件同步，将不会产生新的 OpenDota/周统计快照。

### 5.3 独立工具

| 工具 | 功能 |
|---|---|
| `query_dota_hero` | 官方英雄与技能、先天/天赋、神杖/魔晶、基础数值、效果和注释；支持名称、俗称、槽位、精确补丁 |
| `query_dota_item` | 官方物品目录、装备、消耗品、中立物品、附魔、图纸、价格及合成信息，支持精确补丁 |
| `search_dota_mechanics` | 按官方伤害类型、免疫、可驱散性、施法行为、冷却、距离等条件筛选；描述型效果返回候选及原文依据 |
| `query_dota_patch` | 按补丁和英雄/物品查询版本公告；指定 from_patch 时比较两个完整快照的原始字段差异 |

别名沿用之前整理的英雄与物品俗称（如紫猫、敌法、跳刀），同时使用 Valve 中英文及内部代码。技能还支持按英雄限定俗称（如敌法的烧蓝），以及管理员补充的内部代码别名。若有重名返回候选，不擅自猜测。

### 5.4 第一阶段：版本化技能与装备资料

不依赖 AstrBot 向量知识库把全量英雄、技能和物品切成片段检索。插件直接读取 Valve 官方 `herolist / herodata / itemlist / itemdata / patchnoteslist`，保存同一补丁内的原始资料。每次同步最多同时请求两项详情，分批核对补丁并原子保存进度；默认先同步英雄。某英雄详情失败不阻止装备随后同步，没有完整验收的目录不会作为全量筛选结果发布。装备目录也包括旧物品和特殊模式物品，明确无详情的记录单列为仅目录，不能据此推断购买状态。

- `knowledge_auto_sync` 默认 true，在 active 模式中后台运行；首轮可能需要数分钟至数十分钟，受接口延迟和网络限制影响。`knowledge_batch_size` 默认 24，允许 4–60。总览的手动同步按钮连续执行批次，部分失败则停止等待后续自动重试。手动同步在观察模式也可执行，不调用模型。
- 已发布快照按补丁保留，不用新补丁覆盖旧补丁。默认同步完成后约每小时检查补丁。版本目录获取失败时标记历史或未核实，不冒充最新。首次部署前的历史数值不能通过现在的 API 重建；本阶段不保证逐次捕获无公告的热修，旧 Markdown 不作为全量结构化快照。
- 普通英雄的 Q/W/E 根据三项基础可学习技能的官方顺序推定，R 优先唯一终极技能。先天技能、隐藏技能和额外神杖/魔晶技能不挤占普通槽位。祈求者、凯兹等复杂英雄不强行根据列表位置得出按键，可直接用技能名称；若管理员已核对，可配置 `skill_slots`。
- 详情保留原始等级数组、百分比线索、注释、升级/天赋字段和操作码。只在占位符有明确数值来源时替换，没有来源的值明确留空/未核实，不根据模型常识补造。升级原始字段不直接当成最终加成结果。
- 条件查询的结构化字段依据 Valve 原值及公开枚举解释；文本标签如强驱散、眩晕、沉默、治疗、最大生命伤害等属于带原文的候选，不是完整游戏机制引擎。尤其「技能自身进行驱散」和「技能效果能否被驱散」是不同字段。冷却/施法距离条件取最高提供的基础技能等级，不含天赋、神杖或其他增益。物品查询注明仅目录数量和旧物品可用性限制。

版本公告优先请求 Valve 的 `patchnotes?version=...&language=schinese`，失败时尝试英文。可选 `patchnotes_json` 只读本地官方原版公告 JSON，或 [dotaconstants](https://github.com/odota/dotaconstants) 的 `patchnotes.json`（明确版本键，例如 `7_42`）。公告与原始快照差异分别注明来源；如未获得公告或所需旧版快照，返回缺少数据，不自行推断。接口结构参考 [公开 datafeed 接口记录](https://github.com/taylorferran/valve-api-test-docs/blob/main/DOTA2_API_REFERENCE.md) 与 [ModDota 枚举](https://docs.moddota.com/panorama_enums/)；版本公告的实际在线可用性需在部署机核对。

配置示例（合并到现有 `dota` 模块即可，路径留空则不需要外部资料）：

```json
{
  "knowledge_auto_sync": true,
  "knowledge_batch_size": 24,
  "skill_aliases": {
    "antimage_mana_break": ["烧蓝", "削蓝"]
  },
  "skill_slots": {},
  "patchnotes_json": ""
}
```

推荐验证问题：

- 「敌法的一技能伤害怎么算，大招呢」「紫猫的神杖和魔晶是什么」「敌法十级天赋是什么」。
- 「找出穿透减益免疫的大招」「哪些英雄具有强驱散」「基础满级冷却不超过六秒的技能有哪些」。等待英雄目录发布；分页返回 `next_offset`，可以继续。
- 「7.42 版本敌法改了什么」「上一个版本和当前版本敌法的具体数值差异」。第二种要求对应两份历史快照。

职业比赛目前仍沿用原自主学习的少量公开样本，尚未新增全量 BP、选手打法、按英雄与位置/段位的装备推荐。它们属于后续开发阶段。

排名从已经校验的全量有样本记录计算，不要求模型从向量片段估算。工具字符预算不足时裁减完整条目，不截断 JSON 或数值。对阵数据使用 Valve 的上三角数组；反向胜率正确转换，缺失 0 值作为未知而不是 0%。`dota.default_rank` 与 `dota.rank_labels` 只控制 Valve 对抗原始分组，默认 0 不是全段位。`bracket` 与 `rank_chunk` 不能混用；Valve 的周统计 `week` 只能和明确的 `rank_chunk` 一起使用。

OpenDota 历史比较要求两天均有同口径快照，不把两个抓取快照之差说成实际期间比赛统计。Valve 的周序列在首次成功同步后即可查询。快照日期和详情抓取时间会返回给模型，版本变化、网络失败、无法确定当前物品可用状态都应明确说明。旧 Markdown 中有些技能只有数值而不是完整描述，不能凭空补造效果。详情默认缓存 24 小时；三个来源各自在成功同步后清理超过保留天数（默认 180 天）的内部快照，失败来源保留旧数据，绝不清理旧脚本目录。

### 5.4 通用事实判断

所有人格都附带独立的事实判断规则：工具、知识库、记忆和群友说法属于证据，而非必然正确的结论。对于明显的数据、逻辑、单位、范围、版本或时间矛盾，应主动质疑、核对并更正，而不是强行合理化，也不是无条件附和用户。不增加固定的模型审核调用；数据质量校验由 Python 完成，确需核对时由模型在现有工具轮次和 Token 预算内调用其他来源。

## 6. 人格、关系、习惯与自主行为

默认每 100 条群聊消息学习一批表达；低活跃群也可按时间处理。记忆整理默认每 40 条或 30 分钟，明确记住的请求优先。学习不逐条调用模型、不学习机器人的自言自语、不给不同群复制相同的群友个人信息。

可复用表达、黑话先进入待审核；仅批准的结果进入回复上下文，重复检测更新支持次数。管理页支持编辑、批准、拒绝、回滚、删除。默认不自动批准，且不修改原人格提示词。基础好感度只根据具备本批证据的明确互动按小幅度调整，可手动修改；不会根据敏感属性推断人格。

### 6.1 独立人格与自然表达

- 人格定位是平等的群友，有自己的兴趣、判断和社交边界。原 AstrBot 人格不被永久改写；在模型提示注入时跳过旧层级关系、身份和管理者称呼。仍建议在 AstrBot 人格配置中人工核对并移除过时的从属描述，以便其他聊天链也能沿用独立人格。
- 已知的旧称呼仅在关联人物唯一明确时转换为其正常昵称供模型使用；有歧义的旧记忆留在后台核对，不盲目猜测是谁。用户管理的「迁移旧称呼」支持指定固定身份、旧称呼、新昵称，预览命中的正文、逐条勾选、确认；保留引号中的原话、原证据和历史版本。可同时设置该人的常用聊天称呼，但不会改变 ID。记忆改写后自动失效相应旧向量索引。
- 场景包括闲聊、玩笑、安慰、普通问答、技术问题、游戏问题、纠错与协调。默认最多 3 对相符的正例、1 个反例，共享 700 字符；可以在 `social.examples` 添加 `{"scene":"banter","user":"又白给了","assistant":"这下有素材了"}`。`social.negative_examples` 可编辑 `{"scene":"casual","user":"我要睡了","avoid":"睡吧，我守着。","prefer":"晚安啊"}`。反例仅作为标注过的提示材料，不伪装成助手历史。内置及原人格示例按话题相关性选取，已批准学习用语也须相关；技术/事实问题主要使用相关黑话而非口头禅。
- 在「独立人格与表达」模块编辑 `style_prompt`，默认约束鱼八股、霸总/翻译腔和假装现实经历，允许自然短句、少标点、附和、不强行总结；明确求助仍按需要详细。`casual_silence` 允许普通群聊最终决定不接话，不用于私聊、点名、@、明确问题、工具结果或继续对话。不会增加额外模型审核。
- `tools.contextual_tools` 默认开启：工具定义和专用事实规则按本轮及近期指代话题选择；普通闲聊只保留一个小型的授权展开入口。真的需要未提供的功能时可用 `open_tools`，计入既有工具轮次/次数；模糊的明确查询或仅允许一轮查询时提供足够的已授权工具。关闭该开关恢复完整工具集。没有新的模型判断请求，也没有新增 Provider。
- 短语冷却只统计本会话近期实际发出的回复。默认最近 20 段、30 分钟内出现同一配置短语达到 2 次即尝试避免复读。轻量清理仅处理明显的闲聊模板或重复开头，不触及技术解释、代码、引文和游戏数值。
- 熟悉度根据真实提交的回复轮次累计（分段不重复计数），与已有好感度和近 7 天互动数分别维护。互动计数从 v0.2.0 开始；v0.2.1 按统一身份及人格合计不同会话的真实互动，关系更新可跨同人格会话生效，但不提供具体其他会话内容。历史朋友标签保留熟悉关系；可人工修正熟悉度。轻量社交精力仍按会话及北京时间和间隔恢复，连续参与后下降，兴趣和精力只微调普通插话采样及语气。明确提问、纠错、工具查询不因精力低而被拒绝。

### 6.2 多日习惯印象

`habits.enabled` 默认开启，但每位群友须在当前群主动运行 `/fiyu_habit_on` 同意后才开始累计；也可以在用户管理记录已经获得的本人同意。`/fiyu_habit_off` 撤回授权并清除该人的习惯候选和派生习惯记录，不会删除其他已保存的核心事实。

程序复用现有的记忆批次，按真实身份及不同日期去重，从本人明确分享的游戏、食物、爱好、日常聊天行为形成印象。例如连续三天主动说自己晚上打 Dota，可形成「似乎常在晚间玩 Dota」的印象；一晚连发三条不够成为习惯。仅粗略归纳休闲活动和公开聊天行为，不把发言时间当作真实到家、上下班时间，不推断个人准确行踪、住址或现实路线。本人明确表示习惯已改变，或超过有效期没有证据，旧印象不再作为当前事实。这一类型不具有核心记忆的永久有效性，也不会因重复回忆延长有效期。

### 6.3 自主查阅公开游戏资料

在 **配置中心 → 自主学习** 开启 `research.enabled`。默认每日允许 1 次自主主题（实例总上限，失败或自主跳过也计一次），北京时间 12:00 后、聊天空闲时低优先级执行；多个主题之间默认间隔 60 分钟。`session_umo` 可指定已经观察过、仍授权的群聊，留空时选择最近符合条件的群聊。该会话只决定人格及 Provider，不把私聊或群成员资料交给公开接口。

| 来源 ID | 当前实现 |
|---|---|
| `dota_news` | [Dota 2 官方 RSS](https://store.steampowered.com/feeds/news/app/570/)，可回退至 Steam 新闻 JSON API |
| `dota_pro` | [OpenDota](https://www.opendota.com/) 近期职业比赛列表，最多两场明细的英雄阵容或 BP；小样本不能代表整个职业环境 |
| `dota_meta` | 本地已经校验的 OpenDota 公开比赛胜率快照，单英雄或前六名；无数据时跳过 |
| `cs2_news` | [CS2 官方 RSS](https://store.steampowered.com/feeds/news/app/730/)，可回退至 Steam 新闻 JSON API |

使用固定只读公开接口，不让模型生成任意网络地址、请求参数或主动访问用户账号。暂无 HLTV/Liquipedia 直接抓取功能，也不保证这些站点的普通网页搜索可用；职业赛事资料覆盖受公开来源限制。正常学习仍是一次选题模型调用、一次资料整理，最多 3 次公开接口请求（本地数据无需请求）。同主题 RSS/API 切换和网络重试不重新选题；同主题资料无法获得时，只允许再选一个其他已授权来源的备用主题，优先使用首轮给出的备选，否则至多追加一次选择模型。两次选题共用一个日主题尝试，不重复调用整理模型。默认独立 10,000 Token/天，同时受全局软硬预算与模块调用次数限制。调用前估算，实际以 Provider 返回用量为准；并非供应商绝对计费限额。

#### 6.3.1 数据源故障切换（v0.2.4）

| `research` 字段 | 默认 | 含义 |
|---|---|---|
| `news_transport` | `rss_first` | 优先 RSS（已在目标国内服务器确认可读 XML），失败再试旧 JSON API；可选 `api_first / rss_only / api_only` |
| `network_timeout` | 30 秒 | 单次公开资料请求时间，不影响 `dota.network_timeout` |
| `model_timeout_seconds` | 90 秒 | 选题/整理模型分别等待的时间，不影响聊天模型超时 |
| `network_retries` | 1 | 遇到临时网络故障才有限重试，优先其他接口；两者都计入 `data_requests` |
| `source_cooldown_minutes` | 60 分钟 | 网络/格式失败的共享接口暂时不再自动访问；冷却后可重试 |
| `source_failover` | true | 同主题资料取得失败时，允许最多一个其他来源的备用选题 |

默认每个任务的 `data_requests=3` 仍是硬上限，包括失败请求、重试、同主题接口切换、备用主题和比赛详情。两个公告入口共用稳定的游戏/文章 ID；来源状态在现有 KV 表内持久保存，不进行额外数据库迁移。某个游戏公告暂无近期内容不是共享域名网络故障；已知全部可选资料源都处于冷却或缺少本地快照时不发起模型选题，也不扣当日尝试。若一次实际任务最终仍失败，则留存一次尝试记录，不进行无限次付费重试。

在 **学习中心 → 自主学习 → 检测数据源** 可手动触发一次只读检测：最多三次公开 HTTP 请求（启用的两个 Steam 传输入口和职业比赛列表），只检查实际配置的来源，不消耗模型 Token 或当日主题次数。同一 Steam 入口的两个游戏共享域名状态，页面明确显示最近测试的是哪个游戏，不保证另一游戏一定有数据。失败原因区分请求超时、连接故障、返回格式、HTTP 状态和模型阶段。点击检测后稍等，再刷新页面查看。如果只有 RSS 能访问，可以配置 `rss_only`；不必修改聊天 Provider、Dota 同步超时或部署其他网络服务。

「自主学习」页面列出事实、角色观点、实际引用的来源、资料日期、数据源检测、任务状态和独立 Token 使用量。与近期主题/证据重复的内容默认 7 天内不再整理，过期笔记仍可后台查看，但不会作为当前版本事实自动注入。默认仅对相关话题注入至多两条见闻（共同字符预算 900）；模型可通过 `recall_research` 按需查阅。自主笔记与人物记忆分开，不自动发群、不自动修改人设。

### 6.4 私聊转达指定群

在 **配置中心 → 跨会话消息** 中开启 `relay.enabled`，并配置以下三项（示例 ID 不是真实值）：

- `access.private_enabled=true`，并在 `access.private_users` 填入自己的真实私聊发送者 ID。
- `relay.allowed_users` 只包含明确批准转达的私聊用户 ID。仍需满足私聊白名单及屏蔽规则。
- `relay.group_aliases` 使用 JSON 对应群名和完整 UMO，如 `{"刀塔群":"bot_id:GroupMessage:group_openid"}`。目标必须是已观察到且仍授权的同平台实例、同人格群聊；可以在群里用 `/fiyu_id` 获取 UMO。

私聊示例：

- 「肥鱼，去刀塔群发：今晚九点开黑」：正文清楚时直接提交原文，不调用模型。
- 「肥鱼，去刀塔群组织语言发：今晚九点开黑」：只用明确给出的待发送正文生成一份草稿。收到预览后，在同一个私聊回复「确认发送 任务编号」或者「取消发送」。默认五分钟后草稿过期。

只发送明确授权正文，不引用私聊历史、个人记忆或其他会话。默认每日每个授权私聊最多 5 次、每条最多 600 字，不支持特殊消息组件。失败、超时、进程重启时不自动重发；后台只记录目标、来源会话、任务号和状态，不展示私聊正文。此功能基于 AstrBot 的 `context.send_message` 主动消息能力，QQ 官方平台的实际主动消息权限和时效仍为外部限制；提交成功不是已读或客户端送达保证。

### 6.5 打断的实际边界

不做实时语音级别的 VAD 或独立打断模型。API 请求已经开始时优先等待本次结果安全返回，再判断旧输出是否应丢弃；响应的分段等待可以被立即唤醒。补充/纠正只允许一次自动重组织，避免模型请求在多人聊天中反复取消。已经提交给适配器的消息不能撤回，已经发生的 Token 消耗也不能取消。

## 7. Token、余额与日志

默认优化组合：普通判断采样、短窗口决策、消息合并、少量自动召回、批量后台学习、按需图片/知识工具、工具结果字符和轮次限制。直接 @ 不再额外调用读空气决策模型；固定拒绝回复和已收到的固定戳一戳回复不需要 LLM。

「Token 用量」按日、Provider、模块汇总 `decision / reply / memory / style / vision / vision_observe / embedding / research`，包括未缓存输入、缓存输入、输出、失败和调用次数。优先使用 AstrBot Provider 返回的 usage；缺失用量和 embedding 用估算并标记。`budget.pricing` 可以按 Provider 配置每百万 Token 的 CNY 单价。每日预算默认 `0` 不设硬上限（已有采样、限频和批量机制）；可设置合适的 `daily_tokens` 及分模块调用次数，达到默认 80% 线先暂停非紧急后台处理。场景表达、熟悉度、口头禅、精力、习惯归纳和本地打断不增加每轮固定模型调用次数。

预算是根据已记录用量和预估进行的请求前控制，不是供应商计费系统的绝对硬限额；供应商重试、超时、思考 Token 和进行中的调用可能产生差异。原生知识库内部 embedding/rerank、第三方网页搜索自身计费、其他插件或 AstrBot 自己的用量不包含在本插件 LLM 统计中。建议观察一两天再设置适合群活跃度的预算。

余额监测：启用 `balance_enabled`，选择直接连接 `https://api.deepseek.com` 的已有 DeepSeek Provider，填写阈值、币种、目标 UMO、可选的 @ 用户 ID。余额查询是官方 GET 接口，不消耗对话模型 Token。只有实际观察过并且仍授权的会话可以作为提醒目标；低余额成功提交给适配器后默认 12 小时内不重复提醒。QQ 官方平台仍可能限制主动通知的可用时间或发送配额。

独立日志记录各模块的决策原因、工具状态、用量、错误类别等，默认 `INFO`，需要诊断时切换 `DEBUG`。按北京时间每日写入，默认保留最近 **15 天**，启动和周期性维护自动清理。日志不写完整提示词或 API Key；大文件按日轮转。这与持久记忆数据库完全分开。

## 8. 管理页和数据备份

一级导航使用六个入口，原九个页面通过二级标签访问。侧栏可独立纵向滚动。配置中心内也有六个分类，分别为接入与转达、人格与表达、对话与回复、记忆与学习、知识与工具、模型／预算／日志。各分类内按原配置区显示设置。

| 一级入口 | 页面 |
|---|---|
| 总览 | 原运行总览 |
| 配置中心 | 原配置表单、关键字搜索及 JSON |
| 人物与记忆 | 用户管理、记忆管理 |
| 学习中心 | 语言学习、自主学习（含数据源状态/检测） |
| 跨会话转达 | 原转达记录 |
| 用量与日志 | Token 用量、运行日志 |

- 总览：消息/回复/记忆/待学习/Token 统计，Dota 同步与余额状态，手动管理任务。
- 配置中心支持在全部模块中搜索，也支持在所选分类内按原名称、字段路径或描述搜索。例如，全局搜索「记忆」会找到记忆提取模型，限定「记忆与学习」后只列该分类内的匹配项。可视化筛选与编辑使用同一份草稿，复制、粘贴、导入、导出和保存均处理完整 JSON。保存带版本检查，并自动保留最近 20 份备份。
- 用户管理：统一身份档案默认每个 UID 一条；按会话、真实 ID、统一 ID、会话短 ID、平台昵称或旧别名查询。一键关联记忆，编辑通用称呼、通用别名及按人格共享的关系；展开会话维护本人习惯授权、屏蔽、专属称呼、规则及旧称呼迁移。
- 记忆管理：按关键词/关联用户 ID/昵称搜索，查看并多选关联人物，分类、精度和状态、手动编辑/置顶、历史、归档、恢复、删除。
- 语言学习：表达与黑话的审核管理；Token 用量、独立日志查询。
- 自主学习：公开知识笔记、事实/观点/来源、有效期、任务状态与每日用量；允许手动发起一次受预算约束的检查。
- 跨会话转达：授权配置入口、任务状态及目标，审计记录不显示待发送私聊正文。

配置、SQLite、日志、Dota 缓存均在 AstrBot 的 `data/plugin_data/astrbot_plugin_fiyu_core/`，不在插件代码目录中：

```text
config.json
config_backups/
fiyu.sqlite3
upgrade_backups/
migration_backups/
logs/
dota/
  knowledge/
    snapshots/       # 已发布的独立英雄/装备补丁快照
    staging/         # 未完成批次、可续传
    announcements/   # 已获取的官方版本公告
```

短期消息默认保留 7 天、每作用域最多 2000 条；超限的旧消息可能在后台学习前被清理。长期记忆中的简短证据与历史版本独立保留。数据库中可能存在会话原文和个人事实，注意控制 AstrBot 管理权限、备份范围及保留策略。若要迁移数据，先停止插件/实例，再复制整个独立数据目录；升级前也建议这样备份。单独导出 JSON 配置不包含记忆数据、模型密钥或原知识库。

若只需暂时停用肥鱼聊天链，将本插件模式改 `off` 或禁用，恢复旧聊天插件对应会话设置即可。若回退 Fiyu Core 自身版本，按第 1 节恢复对应旧数据库及代码；不要删除旧插件数据库。

## 9. AstrBot / QQ 已知边界

- 该版本是以 AstrBot 4.29.3 接口为目标开发；升级 AstrBot 后请先测试再启用。
- QQ 必须真实投递普通群消息，肥鱼才能观察 A 与 B 的上下文。AstrBot 4.29.3 官方适配器具有普通群消息和 @ 消息事件解析，但具体非 @ 消息权限由 QQ 平台及你的账号决定；插件无法获得未投递给机器人的消息。
- 官方适配器的引用消息可能没有作者 ID，只有引用内容。此时插件会对最近自己提交且唯一匹配的引用文字做辅助识别，但无法保证识别所有引用。戳一戳同理，以真实适配器事件为准。
- 接管模式使用原生 Provider SDK 的功能调用协议，但自行管理上下文和工具轮次；不会自动运行原 AstrBot Agent 的全部中间件、其他插件的 LLM 请求/回复钩子、图转文字、TTS、定时任务工具或消息装饰。核心收到消息前的原有白名单、安全、限速仍沿用。需要额外工具时应以后续明确、受控的接入方式增加。
- 不依赖 OneBot 模拟官方 QQ 事件，不模拟真实 QQ 发送回执。网络或供应商无法提供数据时保持旧数据、给出失败提示或静默，不伪造结果。
